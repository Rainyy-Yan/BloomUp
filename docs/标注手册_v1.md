# 认知标注手册 v1（待60条开发样本校准）

目标：标注学生当前提问表达的认知任务，不能据此直接判断学生已经掌握对应能力。对象是`question`，必要时结合`prior_context`；禁止查看未来对话或用当前AI答案的高阶语言提升学生标签。

## 第一步：核对解析

先由数据负责人检查30段`parse_review.csv`。填写`roles_correct=yes/no/uncertain`、`reviewer_id`和备注。格式通过不证明语义角色正确：AI回答内部也可能包含Q/A示例。

发现误拆，记录record_id及对应原始行，修正解析规则并生成新版本；不要在原始Excel里直接改写。没有读到的外链、图片和空白记录保持缺失。

## 第二步：逐条判断

| 标签 | 判断标准 | 合成示例 |
|---|---|---|
| 1 记忆 | 识别、列举、定义或复述 | “什么是线性规划？” |
| 2 理解 | 解释概念、解释原因、用自己的话说明关系 | “为什么加入整数约束后求解更难？” |
| 3 应用 | 在明确任务中使用已知方法 | “请用给定单纯形步骤求解这个模型。” |
| 4 分析 | 分解结构、比较条件、分析依赖和机制 | “这两种模型的约束不同会怎样影响可行域？” |
| 5 评价 | 有明确标准的批判、验证、权衡或判断 | “按可解释性和误差标准，哪种拟合更适合这组数据？” |
| 6 创造 | 组合元素构造新方案、设计新模型或新的验证方式 | “请设计同时处理公平性与效率的新目标函数。” |

这些是**所请求任务**的层次。最后一例仍可能只是让AI代做，必须同时标记`outsourcing=yes`，不能写成学生已经会创造模型。

复合问题以有学生文本证据的主要任务为准；不要仅因出现“创新”“批判”就判L5/L6。多个实质任务无法确定主要层次时，在备注列说明并提交裁决。单独的“粒子群算法”可视为概念介绍请求的候选，但需在开发阶段统一规则；上下文不足以确定时NA。

“为什么？”可结合前文理解，但证据列仍引用当前提问中的原词，备注说明使用了哪段前文。高阶推理完全出现在AI回答中时，不能归给学生。

非教学内容、角色不清、文本缺失或确实无法判定，填写NA并解释原因。不要用L1表示垃圾样本。

## 字段填写规范

| 字段 | 可填内容 |
|---|---|
| `bloom_level` | `1`至`6`或`NA` |
| `evidence_quote` | 当前学生提问的精确原文片段；NA可空 |
| `outsourcing` | `yes`、`no`、`uncertain`；是否明确将认知任务外包给AI |
| `insufficient_evidence` | NA填`yes`；1—6填`no` |
| `confidence_1_to_5` | 1—5的主观把握，不是校准概率 |
| `reviewer_id` | 使用稳定的标注者代号，如A/B；不必填写真实姓名 |
| `reviewed_at` | ISO日期，如`2026-09-25` |
| `notes` | 歧义、上下文依据、NA原因等 |

保留turn_id、record_id和原文列，不增删行，不改ID。准备阶段CSV不导出student_key，学生关联在受控内部记录中保留。审阅者A/B各填一份。完成后分别运行校验器；裁决人再合并判断到adjudication表，填写理由。不要把AI输出拷贝到人工表后称为人工独立标签。

上述列名对应准备阶段旧工作表。统一CLI只展示六个不可变字段turn_id、dataset_id、rubric_id、text_hash、question、prior_context，不展示学生标识。解析审查结论进入parse_evidence.json，导入与裁决步骤以 [操作指南](workflow.md) 为准。

## 六级、三阶和HOT

- 六级保持L1—L6。
- 三阶：低=L1/L2，中=L3/L4，高=L5/L6。
- HOT遵循题面：L4—L6。三阶的“高”与HOT不是一个集合。

## 开发到冻结

开发60条完成后整理争议，形成v1.1规则和修改日志。两名人工标注者独立重判受影响的开发条目。此后冻结提示词、标签手册及模型配置，才启用240条audit评估。

风险60条是有目的挑选的候选，需人工确认实际风险类型。不能用其错误率代表全体数据。
