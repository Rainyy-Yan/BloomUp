## 2. 复用现有抽样与标注入口

当前 make_splits 按学生及长文本精确重复关联组划分 development/audit/risk，以种子 20260925 复现；每学期请求 30/120/30 个轮次，再受候选数量限制。它们是准备参数，不是已经完成的样本量，也不是最优样本量证明。语义近重复仍待核验。

|阶段|输入/操作|可验收输出|
|---|---|---|
|数据与解析准入|dataset-import、parse-template、dataset-admit|固定 dataset/admission；候选与准入分母、缺失原因|
|开发样本|development 池的小批次；核对 Q/A 和短追问上下文；明确记录实际模型或人工来源|规则歧义、失败类别、单条成本/耗时；允许修订提示词但保留版本|
|规则冻结|rubric-register --frozen-by；固定模型配置和提示词|规则、提示词、模型版本及开发使用范围|
|独立审计|冻结后才打开 audit；独立人工判断与原预测分别保存|配对表、覆盖率、混淆矩阵、一致性；审计后调参则旧审计不再作为独立证据|
|扩展标注|通过明确质量准则后，按冻结总体处理；失败保留为失败/缺失|原预测、最终采用标签、失败/重试和实际资源账目|
|风险样本|risk 的目的性挑战与极端案例，独立报告|攻击/失效实例，不将其错误率当总体错误率|

现有双人审查和裁决可继续用于人工证据质量；模型—人工一致性与人际一致性须分别命名。没有独立配对时，不能计算该类真实一致性。

六级保持 L1–L6；三阶可选低=L1/L2、中=L3/L4、高=L5/L6，并明确是研究选择。HOT 按题面保持 L4–L6。三阶评估须对同一批配对结果重编码后重新计算，不能复用六级 Kappa。

## 3. 成本模型的可计算输入

以学期等预定层 h 的总体量 N_h、人工复核量 n_h、独立第二次复核量 r_h 为决策输入，0 ≤ r_h ≤ n_h ≤ N_h。模型批量运行成本由 token usage/定价或本地运行资源计算，人工单价由实际耗时或约定单价计算；币种和时间单位须一致。

候选目标：

\[
\min_{n_h,r_h} C_{model}(N)+\sum_h[c_{review,h}n_h+c_{second,h}r_h+c_{adjudicate,h}E(A_h\mid n_h,r_h)]
\]

其中 A_h 为需裁决数量，其期望必须来自试点或明确情景，不能凭空填写。质量约束可写为预先选择的 Q_L(n,r;D_pilot,procedure) ≥ q_*，同时约束覆盖率、预算与必要层的样本数。Q_L 表示基于真实试点和明确重抽样/区间程序得到的保守质量估计，不是现成的保证；既有质量 API 提供点估计；现有 allocation.py 对固定 AI 全覆盖且两次人审的受限政策提供可复算整数规划与情景预计下界，见 [资源配置](allocation.md)。这不是上述一般 n/r 联合问题的求解，也不是实测质量保证。

|缺少输入|允许的输出|不得输出|
|---|---|---|
|q_* 或质量定义未确认|参数情景与预算比较，记录 needs_quality_target|正式最优样本量、已通过真实质量门槛|
|无真实配对试点|符号模型、合成演算或先导样本方案|实测 Kappa、误分类矩阵或质量随样本量的实证曲线|
|单价/usage 未知|资源数量与待填成本项|编造费用或把 null 当 0|
|所有候选方案不满足约束|infeasible 及失败约束|通过降低未知门槛凑出“最优解”|

本方案明确了所需输入，尚未完成成本求解器与真实资源优化。各层加权一致性及区间程序须在正式使用前验证；无质量目标时仅做情景比较。

## 4. 开始真实试点所需信息

可立即做的部分：核对聚合分母、准备版本清单、合成输入合同测试、完善既有规则与实验记录模板。

仅真实模型运行需要：具体模型/版本、运行位置、本地或外部处理范围、与该接收方匹配的数据许可、实际可用凭据、预算上限和日志保留规则。未提供这些信息不执行外部 API，也不假设存在本地可用模型。

真实人工审查需要：实际审阅者、分工、独立性和可投入时间；AI 不填写真人审查身份或重写既有手工标签。

每轮记录输入版本、数量、成功/失败/重试、有效配对量、标签来源、实际成本和限制。模型自报置信度与人工主观把握分别保留，未经校准不称为正确概率。红队编号采用带文件版本的 R01 等，避免引用 GitHub PR 号充当测试案例号。
